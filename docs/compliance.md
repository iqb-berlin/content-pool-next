# Compliance reports

Compliance reports are generated by GitHub Actions and are not committed to
the repository. This keeps generated raw data out of the source history while
retaining reproducible evidence for dependency changes and releases.

## Pull requests

The `Compliance` workflow runs when a dependency manifest, lockfile, license,
or the workflow itself changes. It creates CycloneDX JSON SBOMs for the
backend, frontend, and Keycloak extension. The resulting `dependency-sboms`
artifact is retained for 30 days. The same job verifies that the canonical
Apache-2.0 license text and package declarations remain consistent.

## Scheduled and manual scans

Every Monday, and whenever the workflow is started manually, ScanCode scans a
clean archive of the complete source tree for license, copyright, and package
metadata. The `source-license-scan` artifact is retained for 90 days.

A manual workflow run can additionally enable the Dolos similarity scan. It
compares TypeScript files inside this repository and retains only summary CSV
files for 30 days. Similarity results are indicators for human review; they do
not establish authorship, plagiarism, or a license violation.

## Releases

The release-candidate workflow uses Syft to generate CycloneDX JSON SBOMs for
both published container images and both supported platforms. These SBOMs are
created from the immutable image digests, covered by `SHA256SUMS`, and attached
to the GitHub prerelease. Stable promotion carries the same SBOMs forward
without rebuilding the images.

## Tooling

The pipeline uses open source tools with pinned versions:

- CycloneDX for npm 6.0.0 (Apache-2.0)
- CycloneDX Maven plugin 2.9.3 (Apache-2.0)
- ScanCode Toolkit 32.5.0 (Apache-2.0)
- Syft 1.51.1 (Apache-2.0)
- Dolos 2.9.3 (MIT)

Generated reports describe the scanned revision only. A human review remains
necessary for unclear license expressions, missing metadata, copied source,
and project-specific exceptions.
